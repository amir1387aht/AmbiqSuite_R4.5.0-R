MI BAND 8 NAND / YAFFS2 DIRECT PORT: MSPI 1-1-4 QUAD
================================
Status: guarded experimental startup diagnostics, NOT a validated on-watch driver.
No automatic format, guessed pins, or default partition are added.
Pin defaults now follow the published ATC map; all confirmation guards stay off.
On THIS isolated NAND branch WATCH_NAND_YAFFS2 defaults1: a low-priority startup
worker reports status/capacity after MCU/UART/Nema initialization. Unconfirmed
defaults print SKIP/unavailable WITHOUT touching hardware. Explicit=0 excludes
the worker/storage; main/display/LVGL branches are not changed.
Do not flash a storage-enabled build as proof that its wiring is correct.

PART IDENTIFICATION / EVIDENCE
52audio, 2024-04-15:
https://www.52audio.com/archives/196000.html
The Disney 100th-anniversary Band 8, model M2240B1, includes an NFC chip and
Dosilicon DS35M1GB-IB. This is evidence for that non-Pro Band 8 sample, NOT proof
that every regular/non-NFC/Active/region/revision has the same BOM. Band 8 Pro
uses a different 2Gb part; do not substitute its geometry. Inspect this watch's
marking and confirm its actual device identity before enabling storage.
The teardown's text says "1GB"; Dosilicon specifies 1Gb = 128MiB MAIN data,
not 1 gigabyte. OOB is additional, not filesystem payload capacity.

Original manufacturer product table and current datasheet:
https://www.dosilicon.com/SPI-NAND-Flash.html
https://www.dosilicon.com/resources/SPI%20NAND/DS35X1GBXXX_rev07.pdf
DS35X1GBXXX rev07 (2026-07-15), DS35M1GB-IB (WSON8x6):
- SPI x1/x2/x4 NAND, NOT parallel NAND, not byte-addressable SPI NOR.
- VCC 1.7..1.95V, -40..85C, maximum serial clock 83MHz for 1.8V part.
- ID command 9Fh + dummy byte -> E5h A1h (3.3V Q part is E5h F1h).
  Matching ID is necessary, not sufficient to identify all silicon revisions.
- 1024 eraseblocks, 64 pages/block, 2048 main +128 OOB bytes/page.
  Main eraseblock=128KiB, main total=128MiB. Geometry must be confirmed on device.
- ECC8 per512B; B0h bit4 enabled. C0h bits6:4: 000 clean, 001 corrected1..3,
  011 corrected4..6, 101 corrected7..8, 010 uncorrectable; reserved codes rejected.
- OOB[0] (column800h) is BBM; inspect FIRST TWO pages of each block before erase.
  User spare OOB[0..63]; OOB[64..127] internal parity must never hold YAFFS tags.
  Main+user-spare regions are ECC protected; table3.7 reserves BBM without an
  unambiguous ECC-coverage exception. BBM is read RAW with ECC temporarily off,
  then ECC is restored/read-verified, so correction cannot conceal a marker.
- YAFFS packed tags including YAFFS tag ECC occupy OOB[4..31] (28 bytes on this
  ABI). Physical mapping is custom and NOT interchangeable with a stock image.
  Driver accepts <=60 tag bytes without reaching the internal-parity area.
- Whole-page program loads2048+64 bytes in one command, followed by one execute;
  never separately programs tags in an ECC segment. Marker writes disable ECC
  temporarily, update only OOB[0], then restore and verify B0h.
- Quad commands:6B cache read, opcode x1 +2 column bytes x1 +8 dummy CLOCKS
  +data x4;32 program load, opcode x1 +2 column bytes x1 +data x4, NO dummy
  clocks/write latency. Hardware CS stays asserted across each main+spare burst.
  This is1-1-4 QSPI, NOT4-4-4 QPI or1-4-4 addressing. FF reset,0F/1F features,
  06 WREN,9F ID,13 page-to-cache,10 execute andD8 erase remain x1.
  B0[0] QE is enabled/read-verified only after exact E5 A1 ID/geometry guards.
  Original B0 is saved and restored/read-verified on healthy probe failure or
  unmount. RAW BBM operations preserve QE while temporarily disabling ECC.
  Legacy IOM fallback uses03/02 x1;34 random quad programming is not used.
- Do NOT use133MHz: manufacturer family table4.7 specifies83MHz for1.8V M
  and104MHz for3.3V Q, not133MHz. Apollo4l supports96/48/32/24/... MHz, so
  48MHz is its highest supported clock within this exact83MHz part limit.
  E5 F1/3.3V is rejected, not silently substituted. Bus starts at12MHz; the
  explicit validated-max opt-in selects48MHz after ID/QE verification. Normal
  HAL CLOCK_CONFIG handles clock edges/capture; no divider/register overclock.
- Datasheet maxima: ECC read130us, program700us, erase10ms, reset during erase
  500us; power-up wait5ms; CS deselect>=100ns. Driver margins: read/reset2ms,
  program5ms, erase20ms, and 1us between SPI transfers. Poll iteration limits
  exclude bus-call/preemption overhead; these are not hard RTOS latency guarantees.

SAFE ENABLE PROCEDURE
1. Keep the branch isolated and back up any existing watch NAND data externally.
   Reconcile YAFFS licensing BEFORE distributing enabled firmware.
2. Board defaults in storage/mb8_nand_board.h follow the reversed pin map:
   https://github.com/atc1441/ATCmiBand8fw/blob/931216a15337fa371f3a7d2de6dfb216a90093a4/Pinout_MiBand8.ods
   The same commit's README explicitly identifies that spreadsheet as the
   reversed Mi Band8 pinout. Tabelle1, rows59..62,67,70:
     IO0 / MOSI    GPIO74  function0 = MSPI2_0
     IO1 / MISO    GPIO75  function0 = MSPI2_1
     IO2 / WP#     GPIO76  function0 = MSPI2_2
     IO3 / HOLD#   GPIO77  function0 = MSPI2_3
     SCK           GPIO82  function0 = MSPI2_8 (standard SCK)
     CS#           GPIO85  function7 = NCE85
   Verified against THIS Apollo4l SDK am_hal_pin_fn_list/am_hal_pin.h, not EVB
   reset aliases. CE0 is our software choice: NCE85 NCESRC=36 selects MSPI2CEN0,
   active low; the upstream sheet identifies CS pad85 but not a CE channel.
   CMSIS pad85 supports both MSPI2CEN0=36 and MSPI2CEN1=37. This dedicated
   MSPI2 route does not conflict with display MSPI1 or its reserved pads.
   Driver still checks the actual SDK pad matrix/NCE BEFORE hardware activity.
   The sheet has no variant/revision annotation for these flash rows, no chip
   model, voltage, pull-up values or timing proof. This is REVERSE-ENGINEERED
   SOURCE EVIDENCE, not confirmation every Band8 variant shares the routing.
   Check actual watch continuity and1.8V/pad voltage compatibility; keep
   PINOUT_CONFIRMED,1V8_CONFIRMED,PART_GEOMETRY_CONFIRMED zero until checked.
   Check IO2/3 pull-ups (NOT hard ties to VCC) before confirming quad readiness.
   MSPI1 and known display/power/reset pads11,37..45,86 remain forbidden.
   Legacy IOM mode is NOT configured by this pin map: IOM remains UNKNOWN,
   does not silently fall back, and needs its own independently verified route.
3. Confirm chip marking/revision, geometry, and the independently backed-up,
   block-aligned YAFFS partition boundaries. Set FIRST_BLOCK and BLOCK_COUNT
   explicitly; no whole-chip default exists. Existing Xiaomi filesystems are NOT
   assumed YAFFS. This port will not import/convert/format a factory partition.
   At least16 blocks are required by this configuration;5 blocks are reserved
   for GC, and YAFFS also dynamically reserves checkpoint space.
4. Set the corresponding *_CONFIRMED flags only after those checks. Leave
   WRITES_AUTHORIZED=0. Default CLOCK_HZ=12MHz and QSPI_MAX_CLOCK_VALIDATED=0.
   Scope timings and verify signal integrity before setting the latter to1,
   selecting48MHz after probe. CLOCK_HZ values above12MHz also require that
   validation; unsupported83/96/133MHz requests fail, never clamp silently.
   This48MHz selection is an in-spec controller ceiling, not measured bandwidth.
5. Build from project/gcc, e.g.:
   PATH=/path/to/arm-gcc/bin:$PATH make -j6 WATCH_NAND_YAFFS2=1 WATCH_NAND_MSPI_QUAD=1 CONFIG=bin-nand
   Makefile keeps mount/unmount/open/read/write/fsync/close link-checked. Startup
   calls are now explicitly guarded; do not enable physical confirmations blindly.
   WATCH_NAND_MSPI_QUAD=1 is the storage-enabled default;=0 builds legacy IOM.
   WATCH_NAND_YAFFS2=0 still excludes ALL storage and the new worker.
6. The startup worker is created at the END of mcu_init after UART, GPU/Nema and
   sensor initialization. It first probes E5 A1/status with EMPTY array range
   (first0,count0), requiring electrical/part guards but NO partition guess. Then
   it attempts mb8_storage_mount(true), requiring confirmed partition boundaries
   AND new YAFFS_PROVISIONED_CONFIRMED=1. Confirm an independently provisioned
   YAFFS2 image with this exact tag layout; stock/blank NAND or successful mount
   alone is NOT proof. It never formats. All flags default0.
   No ISR, LVGL/render task, timer daemon, or pre-scheduler calls are supported.
   Queue file requests from other tasks to this worker. YAFFS Direct has a mutex;
   the single-worker rule additionally protects its global last-error state.
7. When physical validation and partition provisioning are complete, explicitly
   set WRITES_AUTHORIZED=1 and call mb8_storage_mount(false) after unmounting.
   It first scans/read-checkpoints READ ONLY, rejects ANY observed scan error,
   then unlocks volatile NAND block protection and remounts read-write.
   BRWD/OTP locking is never overridden. Every read/program/erase/mark callback
   independently enforces the selected partition. No erase or format is implied
   by mount; formatting/provisioning must be a separately authorized operation.
8. File API (all in the same worker, check every return value):
   #include "mb8_storage.h"
   #include "yaffsfs.h"
   if (mb8_storage_mount(true)==0) {
       int fd=yaffs_open("/nand/assets.bin", O_RDONLY, 0);
       if (fd>=0) { /* yaffs_read(fd,buf,len); */ yaffs_close(fd); }
       mb8_storage_unmount();
   }
   Writable mounts use yaffs_open(...,O_CREAT|O_RDWR,0600), yaffs_write and
   yaffs_fsync before acknowledging durability, then yaffs_close. Normal unmount
   saves a checkpoint. No fsync can guarantee survival of arbitrary hardware
   power faults beyond the NAND's specified behavior; validate on the real watch.
9. Resolve gcc/Makefile additions manually when merging with the LVGL8.4 branch.
   Storage includes no LVGL headers/types and changes no UI, allocator, panel,
   profiler, fonts, or FPS files. The sole app hook now starts the guarded
   worker after mcu_init completes peripheral/GPU setup. This branch is based on storage00f74e4, whose base is main d6786d9.

PERFORMANCE / RESOURCE CHOICES
- Dedicated MSPI quad DMA with shared-SRAM,32-byte-aligned1024B TCB and2176B
  bounce buffers. Foreground polls HAL CQ completion without replacing any ISR.
  Serial controls use bounded aligned blocking PIO; actual DEVICE_CONFIG and
  PIOMIXED_CONFIG are both switched for serial/quad, preserving serial SI=D0,
  SO=D1 (SEPIO=1), vs quad SEPIO=0. Read turnaround and write latency are
  independent HAL fields: RX gets8 dummy clocks; TX gets none. Bulk data never
  silently falls back to x1. The worker can be preempted but is synchronous,
  not asynchronous application I/O. No XIP, DDR or display-controller sharing.
- Explicit DAXI flush before submit; HAL callback invalidates after DMA. Caller
  buffers can be unaligned/in TCM; two bounded SRAM copies avoid DMA to unsafe
  user memory. Further zero-copy optimization requires proving memory ownership.
- Full data+tags read uses one cache transfer; tag-only scans fetch just tags.
  Good/bad-block bitmap cache avoids redundant BBM reads on each write/erase.
- Four short-operation cache pages, aligned-write cache bypass, checkpoint
  restore/save and YAFFS summary support retained. NAND ECC, YAFFS tag ECC,
  bad-block handling, verification/retry logic, and normal GC are not stripped.
- File full-scan time and dynamic RAM scale with partition and object count.
  YAFFS requested-allocation budget96KiB (allocator headers extra),256-object cap,
 10 file handles/2 directory-search contexts with CONFIG_YAFFS_SMALL_RAM; buffers/RTOS lock
  are additional. yaffsfs_get_malloc_values reports current/peak YAFFS requests.
  A larger partition/directory tree can fail mount gracefully under this budget.
  Raise it only after measuring remaining UI heap. No new independent sbrk heap.
- Bus transaction timeout10ms, conservative NAND operation bounds above. An
  ambiguous bus/program timeout is never automatically replayed. On bus fault,
  stop CQ/DMA/submodule, power-gate the dedicated MSPI/IOM, retain static buffers,
  poison the transport, and REQUIRE FIRMWARE RESET before reopening. Do not
  power-cycle/retry into a potentially incomplete write without recovery review.
- Any uncertain controller shutdown/interrupt-disable/power/deinitialize failure
  poisons the backend, retains HAL ownership/static buffers and refuses reopen
  until firmware reset. Powered-down MMIO is not accessed after deinitialize
  failure. Healthy close restores B0/QE/ECC first; faulted transport cannot
  promise feature restoration. Never assume an interrupted program completed.
- No measured bandwidth, actual DMA/pad behavior or power-fail endurance claim.
  Quad wire payload ceiling at48MHz is24MB/s before commands, array latency,
  cache copies, polling, YAFFS metadata/GC and ECC; NOT a measured file rate.
  Published routing is mux-compatible; actual-watch continuity/electrical validation
  remains a hardware prerequisite, not production readiness.

STARTUP REPORT / TEMPORARY TESTS (THIS NAND BRANCH ONLY)
Defaults: WATCH_NAND_YAFFS2=1 WATCH_NAND_STARTUP_TESTS=1 WATCH_NAND_TEST_WRITE=0.
Plain ./flash.bat therefore includes the worker/report, not silent support only.
With current board confirmations all0, EXPECTED output includes:
  [NAND] test-write request=0 (default0); actual writes also require ...
  [NAND] probe SKIP/FAIL: electrical/pinout/part confirmations missing; no hardware touched
  [NAND] raw capacity unavailable: ID not successfully probed
  [NAND] filesystem used / total - free: unavailable: ...
  [NAND test] RO checks SKIP: probe/electrical guards failed
  [NAND test] write/delete SKIP: WATCH_NAND_TEST_WRITE=0
These are expected guarded logs, NOT measured on-watch capacity values.

After actual electrical/identity validation, ID-only probe reports identified
raw MAIN geometry capacity134217728 bytes without assigning an array partition.
It cannot read/program/erase/mark/unlock ANY array address in that zero range.
Necessary volatile reset/QE/ECC configuration/restoration is allowed, including
RAW BBM ECC toggling on later partition scans; no protection unlock in RO mode.
If status read fails, status is explicitly unavailable, not invented0x00.
Without confirmed partition/provisioned YAFFS, filesystem report stays unavailable.

Mounted report derives signed64-checked yaffs_totalspace/yaffs_freespace values:
  used_or_unavailable / total - free: <total-free> / <total> - <free> bytes
Each quantity also has KiB and MiB labels, separately from raw chip/partition MAIN.
YAFFS total excludes n_reserved_blocks but NOT every bad/checkpoint overhead;
free includes upstream cache/deletion/checkpoint adjustments. Difference includes
metadata, bad-block and other unavailable space, NOT sum of user file lengths.
Dead blocks, GC-reserved blocks and checkpoint-present blocks provide context.
Negative/inconsistent API returns produce unavailable, never unsigned wrap/clamp.

Temporary tests live only in mb8_storage_startup_tests.c/.h. Default RO tests:
<=3 partition-relative pages x256B read twice/checksum, bounded16 root entries,
at most one nonempty regular file prefix<=256B read twice, no content/name dump,
no symlink following. No confirmed mount/range -> explicit SKIP.
To remove tests LATER while keeping permanent startup print:
  ./flash.bat WATCH_NAND_STARTUP_TESTS=0 WATCH_NAND_TEST_WRITE=0
The two temporary files can then be deleted; permanent worker/report is separate.

EXPLICIT DESTRUCTIVE-TO-TEST-FILE OPT-IN (defaultOFF):
  ./flash.bat WATCH_NAND_STARTUP_TESTS=1 WATCH_NAND_TEST_WRITE=1
This flag alone does NOT authorize any writes: all electrical, pinout, partition,
YAFFS_PROVISIONED and WRITES_AUTHORIZED confirmations are additionally required.
One bounded1024B unique file is exclusively created (O_EXCL,<=8 collision tries),
pattern-written, fsynced, closed, WARM unmounted/remounted RO, reopened and read
back against the pattern. Warm remount discards YAFFS caches so verification
reaches NAND, unlike same-fd read or merely closing a clean cached file. Then
remount RW only to delete THIS created file, check ENOENT and sync. Existing files
are never overwritten/unlinked. Every stage/error/residual test path is reported.
Deletion is logical unlink, NOT guaranteed physical erase; warm remount is NOT
a hardware power-cut endurance/durability proof. Write profile prints its request
BEFORE initial RO phase, so initial RO message is not a whole-boot no-write claim.

Worker retains its TaskHandle suspended after one-shot operation, even if close
fails; no stale deleted-task owner. All startup reads/filesystem/tests execute
there. Future application I/O must be dispatched to this same worker; no request
queue or other task is currently scheduled. Worker stack1536 words=6144B plus
FreeRTOS TCB, temporary static test buffers512B; YAFFS96KiB request budget unchanged.
