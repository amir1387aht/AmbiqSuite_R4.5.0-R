NAND partition configuration
============================

YAFFS Direct uses an inclusive start/end eraseblock range. The adapter resolves
one active YAFFS2 volume at /nand, validates the entire compile-time map, and
passes its physical bounds both to YAFFS and to the DS35 driver. This is not an
on-flash partition table. It does not discover, format, migrate or grant write
access to any existing region.

Configure only after verifying physical ownership, preserving existing data,
and independently provisioning a compatible YAFFS2 OOB4 filesystem:

1. Set MB8_NAND_FIRST_BLOCK and MB8_NAND_BLOCK_COUNT in mb8_nand_board.h.
2. Add every independently verified occupied or reserved region to the map in
   mb8_nand_partitions.c. Set MB8_ACTIVE_PARTITION to the desired YAFFS entry.
3. Set MB8_NAND_PARTITION_CONFIRMED and
   MB8_NAND_YAFFS_PROVISIONED_CONFIRMED to 1 only after verification.
4. Writes become authorized once both confirmations are set. Override
   MB8_NAND_WRITES_AUTHORIZED to 0 to keep the build read-only.

By default the active range is invalid, both confirmations are 0, and writes
are disabled.
Write authorization without both confirmations is rejected at compile time.
The validator rejects empty/out-of-chip ranges, overlapping or duplicate
entries, unknown types, YAFFS ranges under 16 blocks and a reserved active
entry. Unlisted blocks are not assumed to be available. Multiple map entries
are supported but only the selected volume can be mounted at a time.

Each DS35 block has 64 pages of 2048 main bytes; the chip has 1024 blocks.
Bad blocks, GC reserve, metadata and checkpoints reduce available capacity.
The known stock-derived in-band tag layout is not the same as this port's
OOB4 layout. A mistaken range or authorization can overwrite existing data.
