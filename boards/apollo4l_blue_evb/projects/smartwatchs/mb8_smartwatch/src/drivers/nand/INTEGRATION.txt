MI BAND8 STOCK PROFILE / GUARDED YAFFS2 / MSPI1-1-4
================================================
Experimental software, not a validated on-watch filesystem. This isolated branch
is NOT merged into main/display/LVGL. Ordinary builds do not format or overwrite
assets. The explicit FULL_FORMAT boot below is destructive and user-authorized.
No stock firmware binary or guessed stock-filesystem adoption is included.

EXPLICIT DESTRUCTIVE FULL FORMAT / TEMPORARY TEST BOOT
The user authorized discarding stock NAND data. From the project gcc directory:
  make clean
  ./flash.bat WATCH_NAND_FULL_FORMAT=1 WATCH_NAND_TEST_WRITE=0
This image ERASES AGAIN ON EVERY REBOOT. After testing, reflash:
  make clean
  ./flash.bat WATCH_NAND_FULL_FORMAT=0 WATCH_NAND_TEST_WRITE=0
No manual voltage/pin/partition/write confirmation edits are needed FOR THIS
explicit mode. Ordinary board partition/layout/write flags remain unchanged0.
FULL_FORMAT requires NAND=1 and MSPI_QUAD=1; IOM/disabled/conflicting TEST_WRITE
combinations are build errors. It does not download/flash/run stock firmware.

Mandatory preflight BEFORE A0 unlock, WREN06, PROGRAM or ERASED8:
- Runtime E5 A1, geometry/mux, healthy transport and ECC checks remain strict.
- Inventory first/two-page physical factory markers in all1024 blocks; skipbad.
- Firstgood pages0/1 and lastgood page63 each load ONE row/cache. Two complete
  passes compare canonical x1PIO03/12MHz, quadPIO6B/12MHz and quadDMA6B/12MHz,
  all using the same eight256B windows and8 dummy clocks. Serial pass2 must
  also match the retained serial pass1, not overwrite its baseline.
- Any12MHz disagreement or transport/ECC/cleanup failure blocks erasure.
  Bounded first16 bytes of a differing window are labelled read-debug evidence;
  neither serial nor quad is declared correct merely because it repeats.
- Optional quadDMA48 vs canonical12 comparison is a separate diagnostic only.
  Healthy48 data disagreement does not block proven12 consensus; a hardware/
  ECC/policy-reset fault still stops. Subsequent format/program/mount/test data
  ALWAYS use12MHz. Normal FULL_FORMAT=0 quad target remains48MHz.

After12 consensus, unlock only the authorized session. Rev07 section3.2 says
feature registers survive RESET. A0 Table3.1 defined maskBE is BRWD7/BP5:3/
INV2/CMP1;6/0 are reserved. Save originalA0 once, REFUSE BRWD, RMW clear3E
while preserving reserved bits, verify BE only. Healthy shutdown at serial12
issues WRDI04, verifies WELclear, restores/verifies originalA0 BEFORE B0. No
replay on poisoned transport. [NAND protection] UNRESTORED explicitly reports
an incomplete restoration, not invented observed bytes; RESET alone is not
claimed to restore protection. Unmount failure retains handle/ownership and
reports cleanup NOT completed / power-cycle-recovery required, without retry.

Destructive gate and coverage:
1. Erase first factory-good scratch block, program deterministic lane/order-
   sensitive patterns into its first2 pages (main2048 + OOB4..31), read back and
   compare every byte, then repeat12 consensus on known patterns. Physically
   re-read both factory markers uncached; any change stops before mass erase.
2. Erase EVERY factory-good block0..1023, including scratch again. Factorybad
   blocks are never erased/programmed/marked. Verify main2048 and user OOB4..63
   on EVERY page read back as FF. This does NOT claim parity OOB64..127/raw-cell
   erase measurement; first-page marker area is preserved, never repurposed.
3. First unexpected program/erase/status/ECC/read/cleanup fault stops and prints
   FORMAT INCOMPLETE with primary, exact block/page/phase/C0 and cleanup status.
   No automatic new bad marking, retries or pretending the format succeeded.
4. Only complete verified erase+healthy protection/B0 close grants a PRIVATE
   THIS-BOOT runtime own OOB4 YAFFS profile, blocks0..1023, reserve5/cache4,
   original96KiB heap/256object bound. No stock layout/flags/persistent adoption
   marker is guessed. No heap budget expansion or application API changes.
5. Actual YAFFS file tests exclusively create known-pattern.bin in a dedicated
   test directory at sizes0,1,2047,2048,2049,262144 bytes (cross-block). Each
   fsyncs/closes, warm-unmounts/remounts RO, verifies bytes+EOF from NAND, remounts
   RW only to delete its own file/directory, syncs, then warm-remounts RO to prove
   absence. Callback I/O failures latch and prohibit ALL later mutations/mounts;
   upstream close/flush success cannot conceal a failed NAND callback. No unsafe
   forced unmount. Failure can leave diagnostic files; it never cleans unrelated
   files or retries a failed operation. Warm remount is NOT power-loss proof,
   deletion is NOT proof of physical erasure.

Progress yields after bounded page/block/chunk groups in the dedicated low-
priority worker, after GPUready. No LVGL/UI/FPS/display/allocator changes. Rate
lines measure only this watch's timed file API operations with explicit bytes,
ticks/tickHz, including documented sync/close and deliberate yields; not raw
maximum throughput or a claim of48MHz validation. Host/mock rates are NOT watch
measurements. PASS requires all six file sizes plus all healthy cleanup checks.
A normal subsequent image remains RO/unprovisioned until future explicit app

This implementation needs on-watch validation; offline models/ARM linking do

FIRST RAW FAILURE / NO RETRY
A RAW transaction reports its PRIMARY probe/BBM/read result separately from
shutdown and controller-close results. Cleanup NOT_READY never replaces the
original error. BAD is a harmless skip ONLY if feature restoration and bus close
succeeded; BAD+restore failure and successful read+close failure are FAIL.
The worker prints retained evidence immediately BEFORE another open can reset
it, then stops remaining RAW and filesystem checks. First RAW failure is latched
until boot; poisoned MSPI/IOM opens preserve original first HAL evidence.
No later partition-guard message replaces this failure. Identified raw128MiB
remains distinguishable from unavailable filesystem occupancy.
[NAND RAW] gives physical page, transaction phase, primary/shutdown/bus codes.
[NAND core] gives first probe/read/BBM subphase; BBM ECC-off/restore GET-B0 values
are valid only if GET completed. Probe, BBM, shutdown and write-authorized bad
marker B0 checks all use documented-bit maskD1. Raw bytes/XOR remain unmasked;
defined-bit-diff alone determines control-state mismatch, not reserved bits.
[NAND wire] gives failing/last opcode, address, bytes, data-lanes, configuredclock.
[NAND bus] distinguishes DMA enqueue/status/clear/service/errorbits/callback/
bounded poll-timeout from serial PIO/phase switching errors. Safe powered
controller snapshots [NAND regs] are captured BEFORE abort/power gating: raw and
last-polled IRQ, CQSTAT, DMASTAT, DEV0CFG and CTRL1. These are not a hardware dump
or proof of the electrical root cause. No failed HAL call is explicitly stated
for software readback/consistency/busy errors instead of inventing a HAL error.
The first BBM access is6B quad read of1byte atcolumn2048. Actual Apollo4l HAL
build_dma_cmdlist/nonblocking validation does not forbid1-byte non-HEX transfers;
aligned shared bounce and requested bytecount remain unchanged. This evidence
patch does NOT replace quad transport, bypass BBM/ECC, alter data clock48MHz,
change pads/drive strength, round reads, guess a partition, or program/erase.

SERIAL / QUAD CLOCK TRANSITIONS
A later watch log showed a DEFINED bit mismatch: B0 expected0x0c, observed0x86,
XOR8a/defined-diff80 after quad marker reads, at48MHz serial PIO. It is NOT
reserved-only and remains fatal; this log does not prove OTP was programmed.
It also showed unexpected earlier ECC/QE state. No failed HAL call guarantees

All serial PIO now uses12MHz, including feature, row and status commands. Only

set DEVICE+PIOMIXED/address BEFORE raising clock for the next quad DMA. Normal

are updated only after success; any failed transition retains its first error
and poisons the transport. No read retry, forced B0 match or OTP operation.
This conservative mitigation needs an on-watch retest; no claim all reads work.

SERIAL AUXILIARY WP#/HOLD# LEVELS
The next watch log reached both256B quad reads with a matching repeat comparison,
but shutdown GET-B0 returnedff instead of08 (defined-diffD1). That is NOT valid
restoration and still fails. Matching repeats do not authenticate flash contents.
Rev07 sections1.2/2.5/2.6 say HOLD# low with CS# low makes SO high-impedance and
ignores SI/SCLK; the host must not drive IO2/3 during x4 cache reads. They do NOT
establish that QE globally disables HOLD#. Existing MSPI serial PADOUTEN releases
IO2/3 while their pin configuration had no pulls; no guaranteed inactive level
was established by software after a quad transaction. This is a plausible cause
of ff readback, NOT proven on-watch and not proof of OTP state changing.
Serial now preloads GPIO output latches HIGH before enabling GPIO push-pull on
WP#/IO2 and HOLD#/IO3 (stock76/77, SDK selector3 validated before hardware access).
This happens before the initial probe and before every quad->serial command,
including B0 restoration/QE clearing. GPIO HIGH is retained after normal close.
Before quad, both pins return to their board MSPI functions with GPIO output
DISABLED, no forced output and no pull; this remux happens while SERIAL MSPI
PADOUTEN still releases the lines, before quad mode/CS/data. No GPIO drive remains
during quad reads. Existing12MHz serial/48MHz data clocks are unchanged.
The worker has completed checked blocking PIO/non-continuing DMA before changing
phase. A shared bounded1000us DMATIP idle guard runs BEFORE any phase clock/mode/
aux mux change (also initial aux setup and quad arming/shutdown). An active DMA
timeout poisons/records before any such reconfiguration or GPIO drive.
GPIO latch/mux failures retain their first HAL status and signal/stage. Partial
setup never starts a NAND command. No retry/maskedff/OTP access/erase/program or
partition/format changes. New on-watch tests are still required.

PRECISE BUS DIAGNOSTICS / UART
mb8_nand_diagnostics.c records a single-worker snapshot, no printf in HAL/IRQ.
An open failure prints backend/stage/reason, DS35 result, first HAL status(decimal
and hex) if present, requested/selected/initial clocks, controller/CE/profile,
GPIO/function pairs and failing signal. Pin-matrix errors print expected vs
actual SDK function enum; out-of-range pins are never indexed. Failure stages
cover profile, handle/poison, controller/CE/clock, pin range/reserved/duplicate/
mux, HAL initialize/power/config/device-config/enable and individual pad config.
The first HAL error is latched BEFORE cleanup and cannot be overwritten by it.
Preflight failures say no hardware touched BY THIS ATTEMPT. HAL failures instead
say initialization/cleanup was attempted; they do not claim no hardware access.
JEDEC starts only after a successful bus open. IOM fallback also records stages,
but remains unconfigured (IOM=UNKNOWN); no automatic serial fallback occurs.

Shutdown now selects the known12MHz serial probe clock via normal HAL
CLOCK_CONFIG BEFORE SET/GET restoring savedB0 (including QE). Previously those
commands still ran at the selected48MHz bulk clock, and lowering followed only
a successful restore. This sequencing correction is conservative; the user's
E5 A1/status-success +shutdown-failure log does NOT prove its root cause.
48MHz quad-data clock policy is unchanged; serial controls now always use12MHz.
Table3.1 defines B0[7,6,4,0] (OTP_PRT/OTP_EN/ECC_EN/QE), maskD1. All B0
verification now checks EVERY one of those bits; bits5/3/2/1 are reserved, not
claimed stable, writable, busy or restorable. A watch log showed ECC-off expected
0x0f, observed0x07, XOR08: reserved bit3 only, so the old full-byte check falsely
faulted BEFORE any quad cache read. This specific false fault is corrected.
RMW SET values are unchanged; reserved writes are not claimed effective. Initial
OTP-mode rejection and all OTP/QE/ECC mismatch failures remain; no OTP access,
pad/quad-protocol changes or new writes are introduced. A0 protection verification
is separate: the new authorized-write lifecycle below verifies maskBE and
restores the original protection state. No tFEAT/busy wait is specified
for SET FEATURES; existing1us CS gap exceeds Table4.7 tCS>=100ns. No invented
feature-program timing or undocumented command/retry is introduced.
On failure, [NAND restore] prints phase, DS35 result, saved/expected B0 and
observed B0 ONLY if GET completed; otherwise observed unavailable. XOR plus
defined-bit-diff (maskD1) retain raw evidence and show the actual control-state
comparison. Reserved-only differences are tolerated, never treated as ECC/QE/OTP
failures. This does not establish that the subsequent quad data path works.
clock-down, SET-B0, GET-B0 and mismatch are distinct. Runtime HAL phase/PIO/DMA/
clock/close failures preserve their first status before cleanup. Last successful
HAL clock is a software configuration snapshot, not measured frequency. JEDEC
started/not-started is tracked; shutdown errors no longer imply no probe.
Transport/readback failure still blocks further startup reads and requires reset;
no PROGRAM/ERASE/unlock/format or partition-guard changes accompany this fix.

The reported mixed NAND/GPU UART text had a software cause: Ambiq printf formats
into global g_prfbuf BEFORE its UART callback acquires the output mutex. Storage
now uses private512B stack buffer + standard C vsnprintf + existing project
uart_log_write mutex/bounded nonfatal sink. No vendor/GPU/UART code, IRQ masking
or scheduler locks changed. Oversized/formatted-error lines are dropped rather
than emitting truncated PASS; sink failures counted, best-effort dropped-line
summary printed. This fixes NAND buffer ownership, not all legacy printf users.

FILESYSTEM REPORT / WRITE TEST SAFETY
Filesystem scan additionally requires independently backed-up block-aligned
partition, PARTITION_CONFIRMED=1, YAFFS_PROVISIONED_CONFIRMED=1 for THIS exact tag
layout; stock strings or successful mount alone are not compatibility proof.
No stock partition is automatically adopted. At least16blocks,5GC-reserved;
checkpoint additional. Mount always scans RO first and rejects any observed
read/scan error before RW. Every NAND read/write/erase/mark enforces range.
Permanent report uses checked signed64 yaffs_totalspace/yaffs_freespace:
  used_or_unavailable / total - free: <total-free> / <total> - <free> bytes
Plus KiB/MiB, identified raw MAIN, selected partition MAIN, dead/GC-reserved/
checkpoint-present blocks. Total excludes GC reserve but not all bad/checkpoint
space. Difference includes metadata/bad/checkpoint/other unavailable space,
NOT sum of file payload. Negative/inconsistent APIs ->unavailable, never wrap.

if compatible read-only YAFFS mounted, <=3partition pages*256B twice, then an
indented /nand tree of all accessible files/directories with byte sizes.
Names are quoted/escaped (controls/non-ASCII as \xHH, quotes/backslashes escaped);
long escaped names use labelled continuation fragments, never silent truncation.
Symlinks are labelled, never followed; special files are not opened. At most
one nonempty regular file anywhere in the tree gets a <=256B repeat read;
no file contents printed. This is not a forensic dump or stock-layout guess.
Iterative DFS uses ONE directory context (YAFFS limit2), no recursive stack.
Reopened parents replay saved cursors; sole worker/RO mount prevents mutation.
Safety limits: path768 bytes including terminator, depth24 below root,

inode/device cycles, malformed names, any limit/API/log error explicitly report

claimed complete. Yield1tick every16 readdir calls and every directory transition.
