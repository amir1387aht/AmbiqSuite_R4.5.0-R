Mi Band 8 NAND / YAFFS2 integration
===================================

The production firmware contains the DS35M1GB driver, MSPI transport and
YAFFS2 Direct adapter. Startup creates a dedicated worker but performs no
probe, mount, format, file write, or erase. The NAND is accessed only when a
storage job requests it. NAND boot diagnostics and test modes are not built.

Configuration
-------------
The default partition is intentionally unconfigured and writes are disabled.
Set the physical block range and confirmation values in mb8_nand_board.h only
after establishing the ownership of the region and its existing data. The
volume must be independently provisioned for YAFFS2 with this port's OOB4 tag
format; a stock/blank scan is not proof of compatibility. See PARTITIONS.txt.
Do not use the stock region or enable writes based on chip capacity alone.
There is no automatic formatting or migration.

The engineering target is 48 MHz quad data after E5 A1 identification and
QE/ECC setup; commands/probe use 12 MHz. Program-load DMA is conservatively
limited to 12 MHz, and the 48 MHz target path retains the prefix-repair
workaround described as on-watch-tested in commit 8c31519. This does not
establish timing margins across units, voltage and temperature.
The adapter reserves a bounded YAFFS allocation budget; mount can fail if the
configured volume or its object population exceeds the available resources.

Worker API
----------
mb8_storage_startup() is called once by mcu_init. Use
mb8_storage_execute(job, context) from a normal FreeRTOS task to run a job on
the worker. It blocks until completion and returns the job's integer result;
-1 also indicates dispatch failure. The worker owns all YAFFS operations and
serializes requests. A job may dispatch another job recursively. Do not call
from ISR, the timer daemon, or the UI/render task. Do not delete the caller or
release its context while the request is pending. Do not wait inside a job on
another task that is waiting for storage, or deadlock can result.

For example, a callback can mount read-only:

    static int mount_job(void *ctx) { (void)ctx; return mb8_storage_mount(true); }
    int rc = mb8_storage_execute(mount_job, NULL);

A job can also call mb8_storage_mount(false) when the partition, layout and
write authorization are configured, then use YAFFS
Direct APIs on /nand; later jobs can use the same mount. Check each return
value, including yaffs_fsync and mb8_storage_unmount. A file write is not a
durability guarantee until the appropriate sync succeeds. All open handles
must be closed before unmount. On an I/O/scan/protection failure, stop using
the mount and follow the returned status; do not retry ambiguous erase/program
operations blindly. Capacity data is available through mb8_storage_get_usage
from the worker; reported used space includes metadata and unavailable space.

Status
------
This cleanup removes diagnostic/test code but does not prove production
qualification. The actual partition remains unverified, and host simulation
and previous 48 MHz on-watch testing do not qualify power interruption, worn
media, timing margins or all hardware failure modes. No hardware was flashed
or modified by this cleanup. Historical diagnostic code and tests remain in
Git history.
