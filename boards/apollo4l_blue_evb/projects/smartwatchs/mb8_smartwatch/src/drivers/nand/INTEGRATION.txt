FIRST RAW FAILURE / NO RETRY
A RAW transaction reports its PRIMARY probe/BBM/read result separately from
shutdown and controller-close results. Cleanup NOT_READY never replaces the
original error. BAD is a harmless skip ONLY if feature restoration and bus close
succeeded; BAD+restore failure and successful read+close failure are FAIL.
The worker prints retained evidence immediately BEFORE another open can reset
it, then stops remaining RAW and filesystem checks. First RAW failure is latched
until boot; poisoned MSPI/IOM opens preserve original first HAL evidence.
No later partition-guard message replaces this failure. Identified raw128MiB
remains distinguishable from unavailable filesystem occupancy.
[NAND RAW] gives physical page, transaction phase, primary/shutdown/bus codes.
[NAND core] gives first probe/read/BBM subphase; BBM ECC-off/restore GET-B0 values
are valid only if GET completed. Probe, BBM, shutdown and write-authorized bad
marker B0 checks all use documented-bit maskD1. Raw bytes/XOR remain unmasked;
defined-bit-diff alone determines control-state mismatch, not reserved bits.
[NAND wire] gives failing/last opcode, address, bytes, data-lanes, configuredclock.
[NAND bus] distinguishes DMA enqueue/status/clear/service/errorbits/callback/
bounded poll-timeout from serial PIO/phase switching errors. Safe powered
controller snapshots [NAND regs] are captured BEFORE abort/power gating: raw and
last-polled IRQ, CQSTAT, DMASTAT, DEV0CFG and CTRL1. These are not a hardware dump
or proof of the electrical root cause. No failed HAL call is explicitly stated
for software readback/consistency/busy errors instead of inventing a HAL error.
The first BBM access is6B quad read of1byte atcolumn2048. Actual Apollo4l HAL
build_dma_cmdlist/nonblocking validation does not forbid1-byte non-HEX transfers;
aligned shared bounce and requested bytecount remain unchanged. This evidence
patch does NOT replace quad transport, bypass BBM/ECC, alter data clock48MHz,
change pads/drive strength, round reads, guess a partition, or program/erase.

SERIAL AUXILIARY WP#/HOLD# LEVELS
The next watch log reached both256B quad reads with a matching repeat comparison,
but shutdown GET-B0 returnedff instead of08 (defined-diffD1). That is NOT valid
restoration and still fails. Matching repeats do not authenticate flash contents.
Rev07 sections1.2/2.5/2.6 say HOLD# low with CS# low makes SO high-impedance and
ignores SI/SCLK; the host must not drive IO2/3 during x4 cache reads. They do NOT
establish that QE globally disables HOLD#. Existing MSPI serial PADOUTEN releases
IO2/3 while their pin configuration had no pulls; no guaranteed inactive level
was established by software after a quad transaction. This is a plausible cause
of ff readback, NOT proven on-watch and not proof of OTP state changing.
Serial now preloads GPIO output latches HIGH before enabling GPIO push-pull on
WP#/IO2 and HOLD#/IO3 (stock76/77, SDK selector3 validated before hardware access).
This happens before the initial probe and before every quad->serial command,
including B0 restoration/QE clearing. GPIO HIGH is retained after normal close.
Before quad, both pins return to their board MSPI functions with GPIO output
DISABLED, no forced output and no pull; this remux happens while SERIAL MSPI
PADOUTEN still releases the lines, before quad mode/CS/data. No GPIO drive remains
during quad reads. Existing12MHz serial/48MHz data clocks are unchanged.
The worker has completed checked blocking PIO/non-continuing DMA before changing
phase. A shared bounded1000us DMATIP idle guard runs BEFORE any phase clock/mode/
aux mux change (also initial aux setup and quad arming/shutdown). An active DMA
timeout poisons/records before any such reconfiguration or GPIO drive.
GPIO latch/mux failures retain their first HAL status and signal/stage. Partial
setup never starts a NAND command. No retry/maskedff/OTP access/erase/program or
partition/format changes. New on-watch tests are still required.

PRECISE BUS DIAGNOSTICS / UART
mb8_nand_diagnostics.c records a single-worker snapshot, no printf in HAL/IRQ.
An open failure prints backend/stage/reason, DS35 result, first HAL status(decimal
and hex) if present, requested/selected/initial clocks, controller/CE/profile,
GPIO/function pairs and failing signal. Pin-matrix errors print expected vs
actual SDK function enum; out-of-range pins are never indexed. Failure stages
cover profile, handle/poison, controller/CE/clock, pin range/reserved/duplicate/
mux, HAL initialize/power/config/device-config/enable and individual pad config.
The first HAL error is latched BEFORE cleanup and cannot be overwritten by it.
Preflight failures say no hardware touched BY THIS ATTEMPT. HAL failures instead
say initialization/cleanup was attempted; they do not claim no hardware access.
JEDEC starts only after a successful bus open. IOM fallback also records stages,
but remains unconfigured (IOM=UNKNOWN); no automatic serial fallback occurs.

Shutdown now selects the known12MHz serial probe clock via normal HAL
CLOCK_CONFIG BEFORE SET/GET restoring savedB0 (including QE). Previously those
commands still ran at the selected48MHz bulk clock, and lowering followed only
a successful restore. This sequencing correction is conservative; the user's
E5 A1/status-success +shutdown-failure log does NOT prove its root cause.
48MHz quad-data clock policy is unchanged; serial controls now always use12MHz.
Table3.1 defines B0[7,6,4,0] (OTP_PRT/OTP_EN/ECC_EN/QE), maskD1. All B0
verification now checks EVERY one of those bits; bits5/3/2/1 are reserved, not
claimed stable, writable, busy or restorable. A watch log showed ECC-off expected
0x0f, observed0x07, XOR08: reserved bit3 only, so the old full-byte check falsely
faulted BEFORE any quad cache read. This specific false fault is corrected.
RMW SET values are unchanged; reserved writes are not claimed effective. Initial
OTP-mode rejection and all OTP/QE/ECC mismatch failures remain; no OTP access,
pad/quad-protocol changes or new writes are introduced. A0 protection verification
is separate: the new authorized-write lifecycle below verifies maskBE and
restores the original protection state. No tFEAT/busy wait is specified
for SET FEATURES; existing1us CS gap exceeds Table4.7 tCS>=100ns. No invented
feature-program timing or undocumented command/retry is introduced.
On failure, [NAND restore] prints phase, DS35 result, saved/expected B0 and
observed B0 ONLY if GET completed; otherwise observed unavailable. XOR plus
defined-bit-diff (maskD1) retain raw evidence and show the actual control-state
comparison. Reserved-only differences are tolerated, never treated as ECC/QE/OTP
failures. This does not establish that the subsequent quad data path works.
clock-down, SET-B0, GET-B0 and mismatch are distinct. Runtime HAL phase/PIO/DMA/
clock/close failures preserve their first status before cleanup. Last successful
HAL clock is a software configuration snapshot, not measured frequency. JEDEC
started/not-started is tracked; shutdown errors no longer imply no probe.
Transport/readback failure still blocks further startup reads and requires reset;
no PROGRAM/ERASE/unlock/format or partition-guard changes accompany this fix.

The reported mixed NAND/GPU UART text had a software cause: Ambiq printf formats
into global g_prfbuf BEFORE its UART callback acquires the output mutex. Storage
now uses private512B stack buffer + standard C vsnprintf + existing project
uart_log_write mutex/bounded nonfatal sink. No vendor/GPU/UART code, IRQ masking
or scheduler locks changed. Oversized/formatted-error lines are dropped rather
than emitting truncated PASS; sink failures counted, best-effort dropped-line
summary printed. This fixes NAND buffer ownership, not all legacy printf users.
